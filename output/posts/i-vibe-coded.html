I vibe coded something, and I hate it

2026-08-07

After all the hype around LLMs and coding agents, I decided to learn a little bit more how it worked. As a software engineer I was curious on two aspects of it: (1) how its internals work, and (2) how far can we push it. So I thought: what better way to learn it, than trying to build it? And what better way to push to its limits than trying myself to "vibe code" it. I read about Stripes' minions sometime ago and decided to mimic its behaviour for this experiment.

For the experiment I used: GLM-5.2 to review all the code using open code-review from Alibaba. To code I mix it a bit of Claude and DeepSeek V4 Flash. For harness I used Claude Code and Pi. I wanted to keep as much as possible with Chinese providers, as I don't trust the USA ones.

The idea was to create a "one-shot" coding agent, I didn't want the agent to coordinate all the actions. I wanted to use a workflow. Whatever could be deterministic would use a tool and would be a separated node. The probabilistic nodes (the agent) could use different tools to perform the task, but running tests, creating PRs, checking the format of the code, all of that would use deterministic tooling after the probabilistic node. That way I was sure that I would run all the checks I desired.

For the first PRs, I decided I would take a look in all the code, and if I found something I was not aware of, I would find papers that teach me that concept. It worked great, I end up reading a couple of good papers and I felt like I finally grasped how LLMs can use tools and how the whole "coding agents" can work.

In few days of letting one agent coding and another reviewing, I had something working. I called it boitata. The name comes from Brazilian native folklore, a fire snake that protects the forest. Of course, at that point, my workflow was generating so much code that I stopped reading the code. Every weekend I would spend sometime testing the software and checking it seemed to work as I expected.

Boitata became its own thing, when I added typescript and a UI to it, I knew I had lost the game. My last contact with web development was years ago, before Typescript was a mainstream thing. I'm comfortable with JavaScript from the early days of the internet until the first versions of node.js. I broke my own promise of understanding all the code and I was not motivated enough to learn Typescript.

I asked it to create its own documentation. I need to try to make sense of all the code it was generating. I still felt like this experiment could lead to something nice, but the more I look at the result, the more I believe it would take a great amount of human labour to make it something I would like to use.

The code seems good enough. It feels production grade. I would never spend that amount of time on a side-pet project refining comments around the code or even adding so much tests. Normally, on pet-projects I want to learn a specific subject and I focus only on it, everything else that I need to build in order to learn what I really want is just a draft.
